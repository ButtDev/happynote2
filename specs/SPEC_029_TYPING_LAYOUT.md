# SPEC 029 — 세로 받아쓰기 입력 중 키보드 배치

> 2026-11-22 사람 `SPEC_028 4 NG` + 실기기 사진(`.scratch/inbox/20261122-072515-495.jpg`): 세로에서 키보드가 뜨자 영상 띠 한 줄만 남고 아래가 검게 비어 입력 중인 카드가 안 보임.

## 1. 목표
세로 화면에서 카드 「빈칸」 단계 입력칸(받아쓰기)을 눌러 키보드가 뜨면, 영상 상자·필터 툴바·조절 바를 접고 재생 컨트롤 한 줄 + 자막 목록만 남겨 입력칸이 키보드 위에 보이게 한다. 입력을 마치면(포커스가 목록 입력칸을 떠나면) 원래대로. Obsidian이 웹뷰 높이를 줄이든(resize) 키보드가 덮든(overlay) 입력칸이 보여야 한다. 키보드 때문에 높이가 폭보다 작아져 `orientation: landscape`가 켜져도 세로 배치를 유지한다.

## 2. 파일
- `src/ui/EarCoachView.ts`: 모바일 목록 `focusin`/`focusout` → 컨테이너 `is-typing` 클래스, 입력칸을 목록 위쪽으로 스크롤.
- `styles.css`: `.ear-coach-mobile-container.is-typing` 블록.
- `tests/ui/runUiCheck.mjs`·`cases.json`: `expect.typing`.

## 3. 정의
- 입력 중 = 모바일 목록 안 `input`/`textarea`에 포커스, 포커스 시점 화면이 세로(`screen.orientation`).
- 입력 중 배치: 영상 상자 높이 0(iframe은 남겨 소리 계속), 툴바·조절 바 숨김, 목록이 남은 높이 전부.
- 스크롤: 입력칸이 든 카드 위쪽을 목록 맨 위(4px)에 맞춤 — 카드 ▶ 버튼으로 문장 다시 듣기.

## 4. 범위 밖
가로 화면 입력 배치, 받아쓰기 채점 동작, 사전 창.

## 5. 완료 조건
1. [ ] 화면 검사 세로: 빈칸 입력칸 포커스 → `is-typing`, 높이 그대로(덮는 키보드 가정)일 때 입력칸 아래 끝 ≤ 화면 55%, 높이를 480·380으로 줄였을 때 입력칸·재생 컨트롤이 화면 안·세로 배치 유지, 포커스 해제 → 클래스 풀림·영상 다시 보임. 변이(CSS 블록 뺀 사본) 실패 확인 [자동]
2. [ ] 회귀 `verify.mjs --set regression` 통과 [자동]
3. [ ] 실기기 세로에서 카드 「빈칸」 칸을 눌러 키보드가 떠도 그 카드와 입력칸이 보이고, 키보드를 내리면 영상이 돌아오는지 보고 버튼 [수동]

## 8. 가결정
- 사진에 글이 없어 「빈칸 입력칸 → 키보드 → 화면 무너짐」으로 해석 · 이유: 세로 목록의 입력칸은 받아쓰기(`MicroDictationBox`)뿐, 사진에 키보드(Next) · 대안: 사람에게 무엇을 눌렀는지 먼저 묻기(회차 낭비라 안 함).
- 입력 중엔 영상 상자를 높이 0으로(iframe 유지 → 소리 계속), 재생 컨트롤 줄은 남김 · 이유: 받아쓰며 다시 듣기 · 대안: 영상 작게 남기기.
- 스크롤은 입력칸이 든 카드 머리를 목록 맨 위에 · 이유: 카드 ▶ 로 문장 다시 듣기 · 대안: 입력칸만 보이게.
- 가로에서 입력할 때는 그대로(범위 밖) — 포커스 시점 `screen.orientation`이 세로일 때만.
