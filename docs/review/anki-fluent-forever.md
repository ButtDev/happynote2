## 2. 실제 카드 예 (기본 설정, 실제 사전 응답으로 생성)

`tests/fixtures/dictionary/*.json`(실제 dictionaryapi.dev 응답)을 `buildAnkiNote`에 넣어 만든 결과(스크립트 `.scratch/cards.ts`, 문장·영상은 예시).

**① run** — 문장 「So I run every morning before work.」
- Front: `So I ____ every morning before work.` + 그림 + *verb* To move swiftly. / *noun* Act or instance of running… / *adjective* **In a liquid state; melted or molten.**
- Back: `run` `/ɹʊn/` 🔊 · Some talk 01:23

**② show up** (「showed」를 누름) — 「Nobody showed up to the meeting.」
- Front: `Nobody ____ to the meeting.` + 그림 + *verb* To appear, arrive, or attend…
- Back: `show up` (IPA·발음 없음) · 출처

**③ back** — 「I'll be right back after this.」
- Front: `I'll be right ____ after this.` + 그림 + *noun* **The rear of the body…** / *verb* To go in the reverse direction. / *adjective* Near the rear.
- Back: `back` `/bæk/` 🔊 · 출처
- → 문장에서 쓰인 **부사(adverb) 뜻이 카드에도 사전 창에도 없다**. 응답엔 noun·verb·adjective·adverb 4품사가 있는데 `MAX_PARTS_OF_SPEECH = 3`(`src/services/dictionary.ts:30`, `:84`)에서 잘림.

②는 Fluent Forever에 가깝게 잘 나온다(뜻 하나, 빈칸, 그림). ①③은 **문맥과 무관한 뜻이 앞면을 덮어** 「한 카드 한 사실」과 「그림이 주인공」을 깬다.

## 3. Fluent Forever 원칙 대조

| 원칙 (Wyner, *Fluent Forever*) | 지금 | 판정 | 개선 방향 |
|---|---|---|---|
| 번역 대신 그림 — 모국어 단어를 카드에 쓰지 않음 | 한국어 번역 없음, 영어 뜻 + 장면 그림 | ✅ | 유지. AI 한국어 해석(`translationKr`)을 카드에 넣지 않는 지금 선택이 맞음 |
| 그림은 **개인적으로 의미 있는** 것 | 들었던 그 장면(에피소드 기억 단서) | 🔶 | 장면이 말하는 사람 얼굴뿐일 때가 많음(TED 등) → 장면 몇 칸 중 고르기 |
| 소리 먼저 — 발음·IPA를 처음부터 | IPA·발음 있으나 **뒷면에만**, 문장 소리 없음 | 🔶 | 앞면에서 소리를 듣고 떠올리는 카드가 없음. 듣기 앱인데 카드는 눈으로만 푼다 |
| 한 카드 한 사실 | 품사 3개 뜻을 한 앞면에 | ❌ | 문맥 뜻 **하나**만 (SPEC_025 DRAFT) |
| 문맥 속 단어 — 예문 빈칸 | 자막 문장 빈칸 ✅, 구동사는 원형 불일치도 처리 | ✅ | 유지 |
| 카드 종류 3가지(그림→단어, 단어→그림/뜻, 소리+그림→철자) | 앞→뒤(회상), 뒤→앞(인식) 2가지 | 🔶 | 철자 카드(타자 입력) 없음. AnkiDroid 기본 `Basic (type in the answer)`로 가능 |
| 개인 연결(그 단어에 얽힌 내 기억 한 줄) | 칸 없음 | ❌ | 「➕ Anki」 전에 한 줄 메모 칸(선택) |
| 최소쌍·발음 먼저 훈련 | 없음(앱엔 연음 함정 유형 `traps`·`phoneticKr` 있음) | ❌ | 핀 문장 듣기 카드에 소리 힌트를 담아 연결 (SPEC_026 DRAFT) |
| 자주 쓰는 단어부터 | 빈도 정보 없음 | 🔶 | 사전 창에 빈도 등급(상위 2k/5k/그 밖) 표시 후보 |

**기타 설계 문제**
- 뒤→앞 카드(역방향)의 앞면은 단어·IPA·발음·**출처 링크**라, 단어만 보고 뜻·장면을 떠올리는 카드가 됨 — 원칙상 괜찮음. 다만 답면의 문장이 빈칸(`____`) 그대로라 「답 확인」 때 문장 속 단어가 안 보인다(`src/services/anki.ts:192`). 뒷면용으로 **빈칸 없는 문장**(단어 강조)이 있으면 더 좋다.
- 중복 기준이 Front HTML 전체라, 같은 단어를 다른 문장에서 저장하면 새 노트가 된다. 여러 문맥은 학습에 도움이 되지만(변이성), 덱에 같은 단어 카드가 쌓여 간섭이 생길 수 있음 → 「이미 있는 단어」 안내 후보.
- 사전 발음 mp3는 404가 많아 Commons로 바꿈(MEMORY). ②처럼 구동사는 발음·IPA가 없어 뒷면이 비어 보임 → 구는 앞면 소리 TTS가 유일한 대안.
- 태그가 하나뿐 — 영상 id·품사·구/단어 태그가 있으면 AnkiDroid에서 걸러 보기 쉬움(되돌리기 쉬운 변경).

## 4. 사전 활용도 점검

- **잘 된 것**: 낱말 → 구동사 후보 자동(앞 1~2낱말 포함), 발음 재생, 예문, 바로 Anki.
- **문제**
  1. 품사 상한 3에서 문맥 품사가 잘림(③ back). 품사 순서는 응답 순서라 흔한 품사가 뒤에 있으면 사라진다.
  2. 문맥 뜻을 고를 방법이 없음 — 9개 뜻 중 어느 것이 이 문장 뜻인지 사람이 머릿속으로 고르고, 카드에는 품사별 **첫 뜻**이 무조건 들어간다.
  3. 3단계에서만 누를 수 있음(정답 공개 뒤) — 맞는 설계(먼저 귀로 시도)지만, 1단계 빈칸 맞힌 뒤에도 바로 찾을 수 없음.
  4. 조회 기록·캐시가 없음(백로그 ⑦ 캐시) — 같은 단어를 여러 번 찾는 것 자체가 「외워야 할 단어」 신호인데 버려진다.
  5. 영영 뜻이 어려운 경우(③ 「erratically」) 이해 도구로서 약함. 한국어 번역을 카드에 넣지 않는 원칙과 별개로, **사전 창에서만** AI 한 줄 문맥 풀이를 보이는 건 원칙과 충돌하지 않음(카드엔 안 들어감).

## 6. 추린 것 (상위 4 → SPEC DRAFT 3장)

효과 높음 × 노력 낮음~중 × 위험 낮음, 그리고 **듣기 앱이라는 본질**(귀로 회상)을 기준으로 골랐다.

1. **#1 문맥 뜻 하나 + 품사 잘림 고침** → `specs/SPEC_025_CONTEXT_MEANING.md` (DRAFT). 지금 카드의 가장 큰 결점(①③)을 바로 고침. 질문: 뜻 고르기 방식(누르기 vs 첫 뜻 자동).
2. **#3 핀 문장 → Anki 듣기 카드** (+ #4 TTS 소리, #10 원문 뒷면) → `specs/SPEC_026_PIN_LISTENING_CARD.md` (DRAFT). 안 들린 문장이 앱 안에서만 끝나지 않고 간격 반복으로 이어짐. 질문: 카드 모양·TTS 노트 타입을 사람이 한 번 만들지.
3. **#12 핀 간격 재청취 큐** (+ #14 핀 졸업) → `specs/SPEC_027_PIN_REVIEW_QUEUE.md` (DRAFT). Anki 밖, 진짜 영상 소리로 간격 반복. 질문: 간격·표시 위치.
4. (문서로만) **#8 장면 고르기·#7 개인 연결** — 둘 다 사전 창 「➕ Anki」 흐름을 한 번 더 누르게 만들어 마찰이 늘어남. SPEC_025 결과를 본 뒤 정하기를 추천.

**뺀 것과 이유**: #5 원음 구간(약관·기술 위험 큼), #25 녹음(모바일 마이크 불확실), #19 범위 추천(빈도 목록·노력 큼), #2 AI 자동 선택(무료 한도 소모, #1 뒤에 얹을 수 있음).

## 7. 아침에 사람이 고를 것

- 세 DRAFT 중 무엇부터 할지(추천: SPEC_025 → 026 → 027).
- SPEC_025: 문맥 뜻을 **눌러서 고르기**(추천) vs 품사만 맞추고 첫 뜻 자동.
- SPEC_026: TTS 소리를 쓰려면 AnkiDroid에서 노트 타입을 한 번 만들어야 함(AnkiConnect Android에 `createModel` 없음) — 해도 되는지.
